# Rebuilding from total dashboard failure

Order matters: identity and proxies first, then monitoring, then the extras that report into them.
Fill in `.env` from `.env.example` and replace the example domains first (see the top of `.env.example`).

## 0. Assumptions

- Proxmox VE cluster with a shared ZFS storage called `cluster`; LAN `10.0.0.0/16`, gateway/router `10.0.0.1` (OpenWrt), Pi-hole for local DNS.
- Static IPs end in 0 or 5: `10.0.0.x` core static, `10.0.1.x` static overflow, `10.0.2.x` DHCP pool only (see [network.md](network.md)).
- Public traffic only ever arrives through a Cloudflare Tunnel to the `flareon` container; nothing is port-forwarded except WireGuard (UDP 51820).

## 1. Identity: Authentik

1. Deploy the official Authentik docker compose in its own unprivileged LXC (nesting + keyctl).
2. Copy `authentik/blueprints/*.yaml` into the worker container (`/blueprints/custom/`) and apply each:
   `docker compose exec worker ak apply_blueprint custom/<file>.yaml`
3. OIDC providers need `grant_types: [authorization_code, refresh_token]` or logins loop.
4. Client secrets are generated by Authentik; paste each into the matching app (Proxmox realm, PBS realm, Portainer, Grafana, Vaultwarden `SSO_CLIENT_SECRET`, step-ca `ca.json`).

## 2. Reverse proxies

- **LAN:** Nginx Proxy Manager. Recreate the hosts in `npm/proxy-hosts.json` (wildcard cert for the lab domain, access list "LAN only" = `10.0.0.0/16` + VPN `10.100.0.0/24`; a stricter LAN-only list for anything that must never be reachable over the VPN). Put `npm/custom/http_top.conf` in `/data/nginx/custom/`.
- **Public:** `flareon/nginx/tunnel-proxy.conf` on the tunnel container (cloudflared → `localhost:8081`). Install CrowdSec + the nginx bouncer, copy `flareon/crowdsec/` into `/etc/crowdsec/`, and `flareon/nftables.conf` (LAPI only reachable from listed hosts).

## 3. Monitoring: Prometheus + Grafana

1. Create a read-only Proxmox API token (PVEAuditor) for the exporter; SNMPv3 user on the switch.
2. Deploy `monitoring/proxmon/docker-compose.yml` (Portainer stack or `docker compose --env-file ../../.env up -d`). Prometheus config is inline (`configs:`); **bump the config name** (`prometheus_config_vN`) whenever you change it or Docker keeps the old one.
3. Grafana: provision `grafana/provisioning/datasources.yaml`, import `grafana/dashboards/**`.
4. Alerting: create the ntfy contact point from `grafana/alerting/contact-points.yaml` (token from `.env`), then the rules in `alert-rules.yaml` and the policy in `notification-policies.yaml` (Alerting → import, or the provisioning API).

## 4. ntfy

`ntfy/create_squidntfy.sh` builds the LXC (official apt repo, key fingerprint checked), `ntfy/server.yml` is the config (deny-all, no sign-up). Create the publisher (`alerts`, write-only on `squidnet-*`) and run `ntfy/ntfy-pass.sh` for your own login. Publish it through the tunnel with its own `server` block (already in `tunnel-proxy.conf`).

## 5. Homepage

Deploy `homepage/docker-compose.yml`, copy `homepage/config/`. Put `homepage/inventory/` next to it and run `gen.py` on a timer: it writes `services.yaml` from the Proxmox API (read-only token), Docker (via read-only socket proxies) and Pi-hole. `static_services.json` is the hand-made "Home" tab; `names.example.json` shows the MAC → name format.

## 6. squidpatch (patch dashboard)

Copy `squidpatch/` to `/opt/squidpatch` on a node that can SSH to all nodes, install `squidpatch/systemd/*`, enable `squidpatch.service` + `squidpatch-check.timer`. Firewall port 8780 to the proxy + Homepage/Prometheus host only; publish via NPM with Authentik forward-auth. Do **not** add `ProtectHome=` to the service (it needs `/root/.ssh`).

## 7. Suricata

1. On the node to watch, add a port-less bridge (`bridge-ports none`, `bridge-ageing 0`).
2. `suricata/create_squidids.sh` builds the LXC (eth1 on that bridge, no IP). `suricata/etc/suricata/squidnet.yaml` is included from `suricata.yaml` (alerts + stats only); set `HOME_NET` in `suricata.yaml` itself (an override `vars:` block replaces all port groups).
3. `suricata/usr/local/sbin/ids-mirror.sh` + its timer mirror the NIC (and the tunnel container's veth) into the bridge, excluding private hosts by MAC.
4. `squidids-alerts.py` forwards severity-1 alerts to ntfy, rate-limited.

## 8. Remote access + SSH

- `router/wg_router_setup.sh` (WireGuard on OpenWrt, routed, never NAT so VPN clients don't look like LAN), `router/wg-peer.sh` for devices, `router/wg-ddns.sh` for the endpoint name.
- `router/crowdsec-banip.sh` (cron, every 2 min) feeds CrowdSec bans into banIP.
- `step-ca/`: CA VM, Authentik OIDC provisioner with the template in `templates/ssh/`, `trust_ca_node.sh` to roll out `TrustedUserCAKeys`, `ssh-cert.sh` on clients. Back the CA VM up **only** to an encrypted PBS storage.

## 9. Jellyfin standby (optional)

`jellyfin-standby/setup_jellyspare.sh` on the spare node, then `jellyspare-sync.sh` runs at boot + nightly. Add the `backup` upstream (`npm/custom/http_top.conf` and the `jellyfin_ha` upstream in `tunnel-proxy.conf`).

## Gotchas learnt the hard way

- Proxmox `.fw` files: **never put a comment on a section header** (`[RULES] # x`) - the whole section is silently ignored. Check with `pve-firewall compile 2>&1 | grep -i parse` and `iptables-save`.
- Docker host firewall rules: always add `-i eth0`, or they catch Docker's own bridge traffic.
- Incremental `zfs send` must use the same flags as the first full send (`-L` here).
- PBS web shell works only for `root@pam`; NPM hosts proxying a shell need WebSockets on.
